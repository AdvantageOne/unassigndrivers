# Changing the add-in safely (open zone)

You may change the add-in's screen and its in-page behaviour without any dev-team confirmation. What
you may **not** touch is listed in the root `AGENTS.md` and enforced by `.omp/hooks/pre/guardrails.ts`,
`.claude/settings.json`, and `.githooks/`. Read `AGENTS.md` first if you have not.

## Allowed

| Path | What lives there |
|---|---|
| `unassignDrivers.html` | markup, styles, and the UI script — **outside** the `BUILD:core` and `BUILD:client` marker regions |
| `translations/{en,fr}.json` | strings MyGeotab fetches from beside the page |
| `docs/`, `README.md` | documentation |

## Never

- Anything inside `/* BUILD:core:begin */ … /* BUILD:core:end */` or
  `/* BUILD:client:begin */ … /* BUILD:client:end */`. Those regions are generated by
  `build/inline-core.mjs` from `src/core/unassign-core.js` and `src/addin/api-client.js`, and the
  same core code runs inside the Lambda. Edit `src/` instead — which is a gated change.
- `src/`, `infra/`, `scripts/`, `test/`, `build/`, `.github/`, `.githooks/`, `.omp/`, `.claude/`,
  `config*.json`, `package.json`, `pnpm-lock.yaml`, `AGENTS.md`, `CLAUDE.md`.
- Any deploy or AWS command (`scripts/deploy.sh`, `tofu apply`, …). Publishing is the dev team's
  job; your change reaches the tenant when they release it.

## Procedure

1. Make the change in the open zone. For a new or changed string, edit `translations/en.json` (and
   `fr.json`) and use the existing lookup in the page rather than hard-coding text.
2. Keep `SERVER_API_BASE` and the region endpoints in `config*.json` alone — pointing the page at the
   wrong deployment is an infrastructure change, not a UI change.
3. Branch and verify:

   ```bash
   git switch -c ui/<short-slug>
   pnpm test            # must pass: it also proves the built add-in still matches src/
   ```

4. Commit and push the branch, then stop:

   ```bash
   git add unassignDrivers.html translations/
   git commit -m "copy: shorten the schedule card heading"
   git push -u origin ui/<short-slug>
   ```

   Never commit to `main`, never merge, never tag, never release.
5. Report what changed and where the branch is. The dev team reviews and publishes.

## If a gate refuses

The refusal names the path and the rule. Report it to the user and offer to file it as a dev-team
request; do not retry through another tool, do not reword the path, and do not edit the guard.

## Verification that exists

`pnpm test` (unit tests, no network, no AWS, no tenant) and `pnpm run check:addin` (the built add-in
matches `src/`). There is no local browser or live-tenant test: say so instead of implying the change
was exercised against MyGeotab.
